## 可玩性判断

游戏已经有可继续打磨的策略基础。玩家不是单纯点高分店：同路线遇到不同需求组合会出现不同结果；食物、歇脚、购物、景观和少停站之间存在取舍。即时的逐人表态和积分适合保留。

例如这组初级难度的 30 个种子中：

| 控制路线 | 平均积分 | 平均带回人数 | 平均被记住人数 |
|---|---:|---:|---:|
| 长人馄饨 → 墨池 → 五味和 → 五马街 → 码头 | 21.93 | 4.47 / 5 | 3.47 / 5 |
| 五个食物点 | 15.80 | 3.73 / 5 | 2.73 / 5 |
| 五个景观点 | 29.20 | 4.47 / 5 | 3.17 / 5 |

这说明选择会产生后果，也说明“积分最高”“带回最多”“最懂游客”不是同一目标。应明确主目标，分项榜才有解释力。不能把这三条固定路线解释成全局最优策略。

逐段从玩家角度审阅的结果：

| 阶段 | 当前情况 | 对玩家的影响与建议 |
|---|---|---|
| 开局与接团 | 填困扰、接团、需求页、模式选择后才进入排路线 | 目标表达更清楚，但首个反馈前要经过多步；15～30 秒反馈能否实现尚未实测，应计时记录第一家店和第一次自主选择 |
| 排路线 | 多种需求、有路线预览、单片区与商圈两套入口 | 有策略空间。首局建议给一条可修改的短路线，让第一次改动立即出现游客反应；避免先要求记住所有图标与评分 |
| 行走与互动 | 本地跟随和耐心规则；当前版本另有异步 Qwen 进店感想 | 模型能改变表达，目前仍主要由需求标签驱动行为。角色感应来自对玩家选择的记忆、后续反应与短对话，不能只增加台词长度 |
| 到店 | 逐人积分、评分、知识、停留和感想 | 是最值得保留的核心反馈。每次优先突出本次最有感受的游客，完整明细可展开，避免五人每次重复说同一类话 |
| 结算 | 带回人数、记住人数、星评、个人台词、名人、积分明细、券、行程、知识等多段 | 从代码可见信息量较大；实际屏幕拥挤程度未验证。建议第一屏只回答“带得怎样、哪里能改、下一局挑战什么”，详情展开 |
| 再来一局 | 首局重玩前还有五幕结尾，然后选难度 | 有情绪表达价值，但也延迟重试；需真人确认玩家是否误以为已经结束、是否愿意点完。不能据代码宣称它提高留存 |
| 排行榜 | 已有积分、被记住、最快、最丢人四榜 | 已具备榜单入口；当前计算和上报仍不足以承担有奖励的公开竞争，问题见下节 |

规则积分台词在同一类路线的 30 次回放中只有 15～16 种不同文本。它不包含在线 Qwen 感想，不能代表全部台词，但说明只换随机种子不足以持续制造新鲜感。

当前浏览器冒烟脚本也落后于新版流程：tests/smoke-run.js 的 doRoute 点击接团按钮后直接等 page-plan；web/main.js 已在其间加入 page-needs，需要再选择经典或商圈模式。脚本尚未覆盖完整商圈链。恢复浏览器执行后也需要先更新这部分驱动，才能把新版 E2E 记为通过。

## 本轮复现的问题

### 1 高分上报可被伪造成绩，榜位也未按玩家去重

同进程调用当前 POST /api/runs 的实际末级 handler：没有任何行程、没有游客行动记录的样本，提交 500 分返回 200 并进入积分榜。501 分会被拒绝，说明现有校验主要限制数值范围，没有重算过程。

同一个匿名座位连续提交 500、499、498，积分榜占三个位置。server/db.js 按 runs 排序，没有按座位取历史最高，也没有按难度、赛季、规则版本分组。这和文档的“按玩家历史最高成绩排名”不同。

建议先将它定位为演示成绩榜。要承载排名荣誉、奖励或商家利益，应由服务端下发局标识与规则快照、校验或重算行动结果，并按同一座位最佳成绩去重。匿名座位不等于已验证的独立真人。

### 2 模型是否成功响应影响分数

web/main.js 的 shopFeedback 在 source=ai 时调用 addBonus(4)，模板回退不加。控制回放中，同操作的 8 分变成 12 分。addBonus 当前上限八次，存在最多 32 分的额外差额空间。

建议相同游戏行为获得相同积分，Qwen 负责表达。否则网速、限流、费用配置和 API 可用性会影响名次。

### 3 最快榜允许没有完成游览的成绩

使用具有 walk/rush 冲突的合法五人标签组合，排好路线后只推进 1 个游戏分钟、未停任何一站即在中心收队，规则返回 5/5 带回、2 人记住，积分 0。实际榜单查询会收录该结果。

建议最快榜必须先满足同一挑战的有效完成条件，例如完成指定站点与需求后比较耗时。否则最有效策略可能是尽快结束游览。

### 4 午夜结算与“超时 −10”口径有空档

实际调用 addTime(2000) 后时钟被截成 1024，finish 得到 overtime=false、0 分、没有 −10。因为超时扣分只在 clockMin 大于 1024 时触发。回放未真实返程；存活跟随者仍被 finish 标为 home。

需要明确“午夜强制结束”“抵达游客中心”“回头找人后超时”的区别，再决定记录、扣分和榜单资格。现有测试把时钟手工设为 1100 的通过结果，不能覆盖这个实际入口。

### 5 评分来源会被积分台词写错

在不修改游戏文件的隔离夹具里，给长人馄饨设置 4.8 分、来源“携程”，实际积分台词输出“就是这个味，值了（大众点评 4.8）没白来”。scoreStop 的高分文案写死了大众点评，而取分逻辑也允许携程或高德。

建议将平台名与分值一起传递，按原来源展示；评论多也不能直接断言此刻肯定排队。数据真实包括数值和解释都准确。

正面结果：同一家店重访的积分 8 → 8，没有重复加分；本轮没有复现同店无限刷分。

## 对建议文档逐项决定

| 建议 | 决定 | 采纳方式或修正原因 |
|---|---|---|
| 选对店后即时得分、逐位游客表态 | 采纳并保留 | 已有实现。主反馈应明确对应玩家刚做的选择，减少复读 |
| 成绩分享卡、路线主视觉、游客一句话 | 优先试做 | 先复用现有路线与结算数据；所有完成者都能生成，优秀者增加徽章，不必将 80% 玩家排除在分享外 |
| 扫码复刻路线 | 采纳为独立小功能 | 需要路线 ID、版本、店铺快照、挑战参数和导入入口；不会仅靠 Canvas 模板自动完成 |
| 本局榜与多个分项榜 | 有条件采纳 | 本局先看自己的游客反馈；公开榜的每个指标必须解释清楚，并有有效完成条件 |
| 历史最高“代言人第 N 位” | 改后采纳 | 按玩家最佳成绩、难度与挑战版本排名；“先到先得序号”和“高分名次”须分开。称号用明确的游戏荣誉表述 |
| 距离目标只差 37 分 | 有条件采纳 | 必须由真实有效榜单计算；人数不足、不在该难度或数据过期时不显示，不能保证人人永远差一点 |
| 每日换题，只能明天再来 | 修改 | 先做固定种子与评分快照的每日挑战，允许当天重试学习；练习模式另开。当前题库是有出处的静态题，不是已上线的 AI 每日出题 |
| 每月赛季、好友超越推送 | 暂缓 | 先证明一次完整游玩和主动重玩；当前没有完整好友关系与推送能力，不必为此先扩基础设施 |
| 示例券位 | 采纳并保留 | 当前有明确“演示用示例，非真实优惠”，适合展示概念 |
| 单商圈 3～5 家真实商家试点 | 有条件采纳 | 先确认可用券、责任人与核销办法，再以少量真实到店记录验证；不预先许诺固定三个月免费或零成本 |
| 按核销抽佣 | 验证后决定 | 游戏通关、分享、复刻均不等于实体到店。核销不自动等于消费金额；需实际可验证的订单或核销事件才能谈计费 |
| 推荐位、卡面品牌位、榜单冠名 | 后置 | 先有真实使用量。付费展示需清楚标示，不能改变平台评分或公平比赛规则；15% 卡面比例并无项目验证 |
| 跨店通用券、全城自助商家后台 | 暂缓 | 涉及优惠承担、结算、退款与客服，不能按“游戏零成本”排期 |
| 换地图即可复制到其他城市 | 不按原说法采纳 | 代码可能复用，数据密度、交通、营业信息、地方故事、获客及商家运营仍需逐城验证 |
| 分享率 ≥15%、扫码回玩率 ≥20% 即健康 | 仅作为初始假设 | 文档没有来源，项目没有对应漏斗基线。先定义分子分母、观察窗口、去重与样本量，再决定是否采用阈值 |
| 真实评分、冻结数据、小地图优先 | 采纳 | 保存来源与抓取时间，分平台展示。冻结规则需落实为快照版本；不能把当前没有的日更和热度精度当作已经具备 |

## 商业化判断与最小验证

“游戏路线被分享 → 其他人按路线玩 → 真实出门到店 → 消费 → 商家愿意付费”是五个不同事件。当前只有游戏内路线、积分与示例物料；后四步没有本轮证据。复刻路线是游戏转化，不能直接计作实体客流。

分享卡和二维码只是链路的一段。还需落地页、路线保存和恢复、数据版本、店铺变化处理、移动端保存与打开行为，以及可归因记录。文档的“开发成本极低”和“一跳完成、不流失”应改为待实测目标。

建议按以下顺序验证，暂不增加更多榜单或商家后台：

1. 修正上述积分公平、榜单去重与完成资格、午夜和评分来源问题。让玩家知道为什么得分。
2. 在允许启动浏览器的设备上，补经典模式与商圈模式整局、再来一局、断网回退、手机竖屏与横屏。当前尚未完成。
3. 沿用原 PROJECT_STATE 的小型试玩标准：3 位真实玩家，记录能否独立进入第一家店、看懂一次扣分、走到结算、至少 1 人主动再玩。它是小样本体验检查，不是商业化成功证明。
4. 只增加一张可生成的成绩卡和一条路线复刻入口。分别记录有效结算、生成卡、保存卡、带 route ID 的新访客打开、开始和完成挑战；保存图片不等于已经分享到社交平台。
5. 确认有真实玩家愿意在线下照着路线走，再接一家商家的真实核销试点；需要时扩至 3～5 家。以独立到店核销和实际维护成本讨论收费，不从虚拟打卡推算销售额。

最终决定：GO，继续验证游戏反馈与分享路线；NO-GO，当前直接将公开榜单与奖励绑定、启动全城商家收费或按“换地图即可复制”扩城。完整真人试玩仍是未完成项，本报告不提供虚构的可玩性分数或留存结论。
