# 《温州玩家 · 1024分钟》PRD v3.0 —— 行程设计评审

日期：2026-10-24 ｜ 状态：方向确认，P0 待实施 ｜ 基线：PRD-v2（护送机制保留）+ 用户愿景校准
**愿景一句话：玩家是行程设计师，把真实的温州排成一条路线；5 位 AI 游客替你亲身走一遍，用各自拟人的方式给体验打分、评价你的路线设计，并向你提问。**

---

## 0. 方向校准：从「护送」到「评审」

v1/v2 把游客做成了被护送的对象（3❤ + 状态机）。v3 按产品亮点重新定位：

```
玩家 = 行程设计师          排路线是核心创作行为，路线是"作品"
AI 游客 = 5 位评审客户     各有怪癖、拿着真实温州数据、走完要打分要提问
真实的温州 = 评分依据       营业时段/人流/距离/价格/冷知识——判断落在事实上
```

四要素差距盘点（2026-10-23 评审结论）：
| 要素 | 现状 | v3 补齐 |
|---|---|---|
| 真实的温州 | 19 真实地点 + 52 带出处知识 + crawl-lab 真实商户数据 | 真实数据进判定：扑空/赶上/人流/步行时间 |
| AI 游客去体验 | 只有 3❤ 状态 | 每人一份「行程体验账」（事件流现成，13 类） |
| 拟人打分 | 无 | 每人 ★ 评分 + 拟人评语 + 加分点 + 扣分点 |
| 给路线打分+提问 | 无 | 路线总评 + 每人一个问题（问题=重玩钩子） |

护送玩法（心/哄/走丢/名人问答）**全部保留**——它们是体验账的素材，不是被替换的对象。

## 1. 核心循环三幕

### 第一幕 · 行前设计（排路线页升级）
- 保留：点 3~5 个地点、按序走。
- 新增**行前疑虑**：选定每个地点后，游客基于「人设 + 真实数据」即时给一句疑虑/期待（本地规则生成，零延迟）：
  - "五马街的手信店 18:00 关门，我们这程走到那儿 19:20？"
  - "楠溪第一楼 13:00–15:30 歇业，咱们 12:40 到正好饭点。"
  - "12 点的五马街人最多，你确定？"（怕挤挤专属）
- 数据不足的地点疑虑退化为现有 preview 表情句——**宁缺勿编**。

### 第二幕 · 行中体验（护送玩法 + 隐式记账）
- 护送机制不变（心/哄/坐下/跑开/名人问答/±♥ 浮字/需求图标）。
- 新增**事实事件**（进 events 流）：每次到站，本地规则对照 `facts` 校验 → `arrived_open / arrived_closed / sellout_risk / crowd_peak / crowd_calm`。
- 扑空的戏剧呈现：到打烊的店，前台页换皮——"铁门拉下来了"，该游客危机台词，吃不到=不满足。

### 第三幕 · 行后评审（结算页大改）
- 每位游客一张**评审卡**：
  ```
  😣 怕挤挤   ★★★☆☆ 3.5
  评语：路线聪明，绕开了五马街最挤的两小时。但仓桥街那段人也不少，我全程贴墙。
  加分：把茶摊安排在午后，我喘上气了。
  扣分：码头看完落日直接散场，我没缓过来就走。
  问题：下次能不能把塘河夜画排进来？我想看晚上的温州。
  ```
- 路线总评 = 5 人分的拟人化汇总（"5 位游客给这趟打了 3.6 星 · 本地通路线还差一步"）。
- **问题钩子**：游客的问题存 localStorage，下一局排路线页显示「上局没劲儿问：江心屿的双塔晚上真的会亮灯吗？」——串局成连续剧。

## 2. 评审机制规格：事实与修辞分离

### 2.1 本地体验评分器（事实层，零 LLM，断网兜底）
每位游客 i 的总分 = Σ(每次停站体验分 × 权重) / Σ权重 + 全局修正：
- 基础 3 分/站；该站类型命中 i 的需求 → +2 且满足时锁定高分；非需求站 -0.5
- 真实时段校验：营业中 +0.5；**扑空 → 该站记 1 分**（事实事件驱动）
- 停留 ≥ 建议时长 +0.5；人潮 peak 到达且 i=怕挤挤 -1；冲突被帮 +0.5；走丢 -1
- 权重：需求站 ×2，其他 ×1。总分映射 ★（1~5，半星步进）。
- 事实标签随分生成：`已打烊` / `赶上饭点` / `人潮峰值` / `全程没掉队` ——这些是给 LLM 的"编不了的事实"。

### 2.2 LLM 评审卡（修辞层，复用现成 AI 管线）
```
POST /api/review
{ seat, events: [...13类事件流...], facts: [事实标签], route: [...],
  guests: [{tag, line, satisfied, score, factTags}], knowledge: [本局触发的知识] }
→ { ok, reviews: [{ tag, score, comment(≤40字), pro(≤16字), con(≤16字), question(≤20字) }], source: 'ai'|'local' }
```
- 复用：人设卡构造、sanitize、敏感词过滤、超时回退全套（ai.js 改造为多卡评审）。
- 限流 3 次/分/IP（一局一次）。超时 6s（评审在结算场景，前端**先显示本地评分器的模板卡，AI 回来原位淡入替换**）。
- 输出 JSON 校验失败 → source:local。

### 2.3 事实数据源
`content/facts.json`（crawl 产物转译，见 docs/DATA-REQUIREMENTS.md）：hours/selloutBy/crowd/walkMatrix/bestTime/localTip。规则层只消费 verified/platform 级数据做判定；hearsay 级只允许进 LLM 评语素材。

## 3. 数据需求（摘要，完整抓数规范见 docs/DATA-REQUIREMENTS.md）

**好玩倒推**：游客的评审要"狠、准、有出处"，缺数据就只能夸夸其谈。按戏剧时刻倒推六类：
| 数据 | 解锁机制 | 戏剧时刻 |
|---|---|---|
| 营业时段/售罄时间 | 扑空/赶上判定 | "到了才发现铁门拉下来了" |
| 分时段人流 | 拥挤判定 | "12 点的五马街，你偏带我去" |
| 地点间步行时间 | 行程可行性评审 | "码头到墨池要 35 分钟，你排的 10 分钟" |
| 排队时长/价格/招牌 | 消费评语 | "排队 25 分钟，催催炸了" |
| 最佳体验时段 | 惊喜时刻 | "17:30 的江滨，落日正打在双塔上" |
| 冷知识彩蛋 | 提问素材 | "考你：朔门古港的瓷片是哪个窑的？" |

数量红线：12 个市区地点 hours 全覆盖；主干步行矩阵 10×10；每点 ≥1 条 localTip；售罄/排队 ≥4 家。**宁空勿编，空=不触发事件，编错=口碑事故。**

## 7. 风险
| 风险 | 对策 |
|---|---|
| LLM 评审幻觉（编造没发生的行程） | 事实层先行：分数+事实标签本地算死，LLM 只润色；prompt 明示"只能引用给定事件" |
| 真实数据过期（营业时间变更） | facts 带采集时间与置信级，低置信只进评语；封面页标"数据采集于 10-23" |
| 评审接口被刷 | 限流 3/min/IP + seat 校验 |
| 现场断网 | 本地评分器即完整体验，LLM 层纯增强 |
| 时间不够 | P0 砍序：先评分器+评审卡（本地版已可演示），LLM 最后接 |
