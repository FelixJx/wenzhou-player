日期：2026-10-23 晚 ｜ 状态：实施中 ｜ 基线：PRD v1.0 + 2026-10-23 晚间扩充（19 地点 / 52 知识 / AI 大脑）+ 实玩评审（四局全流程实测）

## 1. 特性规格（P0 = 本次实施）

### F1 商店前台页（替代停站卡）
- 触发：`stay` 命令（所有 stayMin>0 的地点）。暂停不变（`setPaused`）。
- 布局（半屏页，地图仍在上方可见）：
  - 头部：类型图标 + 地点名 + `+N 分钟`。
  - **进店游客行**：本站被满足的游客头像 + 各一句对店的评价（取 `content/guests[tag].lines.resolved`，`{place}` 替换）；若无人被满足，显示常驻一句（如"看看就走"）。
  - **温州一句话**：knowledge 文本 + 出处，字号加大，常驻到玩家关闭为止。
  - 底部：`继续出发` 单按钮（唯一关闭方式，无定时器）。
- 时钟语义配合 F4：页面停留不烧时间。
- 验收：EVAL-v2 B-F1。

### F2 名人世界相遇
- **F2a 立绘**：运行时 canvas 绘制 24×24 像素像 → dataURL，`image-rendering: pixelated` 放大展示。每人一套配色（谢灵运·青衫/王羲之·紫袍执笔/文天祥·玄甲/苏步青·灰西装），零图片资产。
- **F2b 原作句展示**：卡正面加 `card.quote` 区块（「池塘生春草，园柳变鸣禽。」+ 出处 + "原作"角标）；无 quote（苏步青）不显示。数据早已在 `buildCard` 里，只差 UI。
- **F2c 触发轮换**：`celebrity.checkAll()` 返回全部匹配者，rules 按 content 顺序取第一个未出场者。谢灵运先在码头出场后，墨池就会遇到王羲之（确定性，不随机，测试可断言）。
- **F2d 描"永"字小游戏**（王羲之 ask:'play'）：全屏卡上嵌入 canvas：显示"永"字淡色笔画路径（5 个锚点折线），玩家手指沿锚点滑动，走完全程且偏差 < 阈值 → 成功（金光 + `全队 +1❤` 音效）；失败 2 次自动放行为"点头走过"。跳过链接保留。成功/失败的 `choose('celeb_wang_xizhi', 'a'/'b')` 语义不变——**规则层零改动**。

### F3 开场横幅（苏步青不挡路）
- `when:'start'` 的名人命令带 `when` 字段（rules 已可判）；main.js 识别后走 `ui.showBanner`：顶部横幅（头像 + 一句话），5 秒自动收起，**不暂停、不挡操作**。收起时自动 `choose('celeb_' + who, 'b')`（无成本，规则层零改动）。
- 苏步青结算台词由 F8 渲染。

### F4 时钟走路才走
- 规则：`run.tick()` 仅在 **玩家移动中** 或 **有游客脱队（sit/runaway，他们的超时仍在走）** 时被喂入；停站页/中断/名人卡期间本就暂停（不变）。
- 效果：站着想路线不烧时间；1024 分钟的紧迫感集中在"路上"。催催催 speedMul 语义不变。
- 副作用接受：人潮区掉心要求队伍在区内"停留"，现在停留不烧钟 → 怕挤挤只在穿行时掉心，难度略降，P1 观察后调 `crowdDropEvery`。
- 实现：`engine.isPlayerMoving()` 新接口 + main.js tick 门控。**rules/测试零改动**。

### F5 结尾交还玩家
- `endingDecideMs` 默认改 0 = **不自动选择**；"继续回家"按钮加呼吸动画引导；"回去找他"不设时限。
- PRD v1 的"高潮停在两个按钮不点"从演示技巧变成真实体验。

### F6 路线链修复（两个 bug 一起）
- 零停站地点到达后（小巷/厕所）同样调用 `nextLeg()`。
- 空闲回归：玩家手动点地改道后，若 **4 秒无输入且未在路线点** → 自动走向下一个未访问路线点，底部 toast「回到路线：五马街」。
- 效果：改道仍是自由的，但永远不会"永远走丢"。

### F7 "那句话的旅程"页
- `ui.showMine(m)` 全屏页替代 toast：玩家那句话大字展示 + 两个数字（去了 N 个人的队伍 / 被带回家 M 次）+ 一句动态文案：
  - N=0：「你的话还在池子里，等下一队人来抽中它。」（单人测试不再像坏了）
  - N≥1：「有 N 个陌生人替你把它带进了温州。」
- 服务端 M4 已由并行会话修复（`insertRun` 按 `result.troubles` 绑定），本特性纯展示层。

### F8 结算页补全
- 知识标题按实际条数：「今天你认识了温州的 N 件事」；N=0 显示既有兜底句。
- 渲染 `result.celebrityLine`（苏步青"你用了 N 分钟"）+「今天遇见的人」头像行（`result.celebrities`）。
- 称号文案接 `content.ending.resultTitles`（键 fast→rush 兼容映射）。
- 都行哥结算台词固定 `resolved[0]`（PRD v1 指定句，14 字按 ISSUES #3 预留宽度）。

### F9 程序化音效（web/sfx.js，零资产）
- WebAudio 合成：bubble(泡) / heart(+叮) / drop(降) / stay(门铃) / celeb(琶音) / win(大调) / lose(小调) / click(嗒) / back(归来)。
- 主音量 0.15；首次用户手势 init（自动播放策略）；静音开关在暂停页，状态存 `localStorage.wz_sfx_mute`。
- 挂接点：main.js 的 handle() 命令分发（bubble/heart/lost/stay/celebrity/end）+ 结尾按钮。

### F10 地标像素图（scripts/gen-assets.js）
- Node 零依赖脚本：RGBA 缓冲 + 手写 PNG 编码器（zlib + CRC32），2x 最近邻放大出像素颗粒感，生成 `web/assets/wuma.png(160×120 牌楼) / mochi.png(96×96 墨池亭) / center.png(160×110 游客中心)`。
- `render.loadSprites` 探测逻辑不变——文件存在即自动替换程序化画法，404 消失。
- 可重跑：`node scripts/gen-assets.js`。

### F11 渲染修正
- 气泡 `bx` 钳制在 `[4, view.w - bw - 4]`，不再裁半。
- 实体标签防重叠：同帧按 sx 排序，相邻 <44px 时逐个上下错位 14px。

### F12 结算文案修正（不与并行会话重复的部分）
- 走丢者台词：仍用 `LOST_LINE`（测试锚定），但带回而未满足者用各自 `unresolved`（现状保留）；称号接 content（F8 内）。
- ~~都行哥固定句~~（并入 F8）。

### F13 心声系统（互动密度主升级）
- 新触发点（全部走既有 `bubble` 命令，rules 内加判断，≤10 字，每触发点每局限 1~2 次）：
  - 到达任意地点：未满足的对应游客冒泡期待句（food→"闻到香味了"，shop→"就是这家！"，复用 `lines.warn` 池，与 satisfy 不同句）。
  - 路过（非路线）店/看点：对应游客 30% 概率冒泡回头句（"哎，那边……"）。
  - 停站页内（F1 页面上）每人一句静态心声，随页面展示——**这条最划算：一次停站 5 句台词，互动密度立刻×5**。
- 数值护栏：全局台词冷却 4 游戏分钟，单游客每 2 游戏分钟最多 1 句，防止刷屏。

## 3. 平板 3:7 规格（F14，P1 赛前可做）

### 3.1 布局
```
┌──────────────────────────────┬────────────────┐
│                              │ 旅行手册 (≈30%) │
│   温州地图 (≈70%)            │ ┌────────────┐ │
│   现有 canvas，相机不变       │ │队伍│行程│卡集│ │
│   viewWorldWidth: 280→520    │ ├────────────┤ │
│   （engine.snapZoom 自动适配）│ │ 队伍页签：  │ │
│                              │ │ 👤avatar×5 │ │
│ 顶部 1024 时间轴保留          │ │ 心情emoji  │ │
│                              │ │ 实时心声   │ │
│                              │ ├────────────┤ │
│                              │ │ 行程页签：  │ │
│                              │ │ ①墨池公园 ✓│ │
│                              │ │ ②小吃街 ●  │ │
│                              │ │ ③茶摊  ○   │ │
│                              │ └────────────┘ │
└──────────────────────────────┴────────────────┘
```
- 断点：`min(aspect-ratio) > 1.1` 或宽度 ≥700px 时启用；竖屏手机维持现状。CSS 媒体查询 + `#handbook` DOM 层，canvas 容器宽度联动 `engine.resize`（ResizeObserver 已存在，零引擎改动）。
- 数据全部来自既有 `run.state`（guests.hearts/status/satisfied + route/visited），无新后端。

### 3.2 拖景点进手册
- 来源：地图地点徽章（`render.badgeRects` 已有屏幕矩形）长按 220ms 起拖，幽灵图标跟随；落点在手册行程页 → 加入路线（复用 `planRoute` 预览，游客头像在手册顶部实时变 😊/😟/😐）。
- 手机端等价交互：点徽章 = 现状（goTo）；**加号角标**点一下 = 加入路线（等价于拖拽），不新增学习成本。
- 移除路线：行程页条目左滑/点 ×。约束沿用 routeMin 3 / routeMax 5。

### 3.3 手册页签内容
- **队伍**：5~7 张游客卡（头像/名字/3❤/心情 emoji/当前心声一行）。心情映射：satisfied→😍、3❤→😊、2❤→😐、1❤→😟、0❤/sit→😫、runaway→😢、lost→👻。点卡片 = 哄（现有 onTapGuest 语义 + calmLeft 显示）。
- **行程**：路线列表（图标/名/状态 ✓已访 ●当前 ○待访）+ "回到路线"按钮（F6 的手动版）。
- **卡集**：本局名人卡缩略（立绘 + 名字，未遇显灰）+ 已收集知识（本局 knowledgeSeen）——给现场演示一个"翻手册"的高光动作。

### 3.4 工作量与风险
- 前端 1 文件（web/handbook.js）+ style.css 增量 + main.js 三处状态推送；无引擎/规则改动。预估 0.5 天。
- 风险：拖拽与相机手势冲突（长按阈值规避）；横竖屏切换时 canvas resize（ResizeObserver 已兜底）。
